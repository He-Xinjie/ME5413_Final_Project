# 3D Box Detection & Deduplication 技术文档

## 1. 总体思路

场景中散布着标有数字 1-9 的 0.8m 立方体箱子，机器人在巡逻过程中需要对每种数字分别计数。
核心难点：同一个箱子会被相机多次看到（不同角度、不同距离），必须去重。

**解决方案：RGB-D 深度相机 + 模板匹配 + 3D 全局聚类投票**

整体流程：

```
RGB 图像 ──────> 模板匹配 ──> 识别数字 + 得分
                                   │
Depth 图像 ──> 取检测中心深度 ──> 反投影到相机3D坐标
                                   │
                              TF变换到 map 坐标系
                                   │
                           距离聚类 + 投票去重
                                   │
                         输出去重后的各数字计数
```

---

## 2. 识别部分

### 2.1 深度相机配置

替换了原始的 RGB 相机（Pointgrey Flea3），使用 Gazebo 的 `libgazebo_ros_openni_kinect.so` 插件提供 RGB-D 数据。

**相机参数（`depth_camera.urdf.xacro`）：**

| 参数 | 值 | 说明 |
|------|-----|------|
| fps | 10 | 降低帧率减轻 CPU 负担 |
| width | 480 | 图像宽度 |
| height | 360 | 图像高度 |
| near | 0.1m | 最近裁剪距离 |
| far | 10.0m | 最远裁剪距离 |
| hfov | 1.047 rad (60°) | 水平视场角 |

**发布的话题：**
- `/front/image_raw` — RGB 图像
- `/front/depth/image_raw` — 深度图像（32FC1，单位：米）
- `/front/depth/points` — 点云（PointCloud2）
- `/front/camera_info` — 相机内参

### 2.2 模板匹配

使用 OpenCV 的 `cv2.matchTemplate` 进行数字识别。

**模板来源：** Gazebo 模型中每个数字箱子的纹理贴图（`me5413_world/models/numberN/materials/textures/numberN.png`）。贴图是箱子的展开图（3x3 网格），取中间行最右列的面作为模板。

**匹配方法：边缘 + 灰度 双通道融合**

```
最终得分 = 0.5 × 边缘匹配得分 + 0.5 × 灰度匹配得分
```

- **边缘通道**：对 RGB 图像和模板分别做 Canny 边缘检测（阈值 50/150），再做归一化相关匹配（`TM_CCOEFF_NORMED`）。对光照变化鲁棒。
- **灰度通道**：直接用灰度图做归一化相关匹配。保留亮度/纹理信息。

两者融合可以兼顾结构特征和纹理特征，比单用任何一种更稳定。

**多尺度搜索：** 对模板按 4 个缩放比例（0.5, 0.7, 1.0, 1.3）分别匹配，适应箱子在不同距离下的大小变化。最小检测尺寸 25 像素。

**区域去重（同帧内）：** 同一帧中相邻位置（50 像素内）的多个检测结果只保留得分最高的。

### 2.3 检测阈值

| 阈值 | 值 | 用途 |
|------|-----|------|
| `draw_threshold` | 0.45 | 在可视化图像上画框（仅显示用） |
| `count_threshold` | 0.60 | 触发 3D 定位和计数（必须达到此得分才纳入去重系统） |

## 3. 3D 定位部分

识别到数字之后，需要知道这个箱子在全局地图中的位置，才能做去重。

### 3.1 深度读取

在检测框中心像素处取一个 5×5 的小区域，用中值滤波得到稳定的深度值（滤除噪声和空洞）。

```python
depth = median(depth_image[v-2:v+3, u-2:u+3])  # 忽略 <0.3m 和 >10.0m 的无效值
```

### 3.2 反投影到相机 3D 坐标

利用相机内参（从 `/front/camera_info` 获取），将 2D 像素坐标 + 深度反投影为相机光学坐标系下的 3D 点：

```
X_cam = (u - cx) × depth / fx
Y_cam = (v - cy) × depth / fy
Z_cam = depth
```

其中 `fx, fy` 是焦距，`cx, cy` 是光心。

### 3.3 TF 变换到 map 坐标系

使用 ROS 的 TF2 系统将相机坐标系（`front_camera_optical`）下的 3D 点变换到全局地图坐标系（`map`）：

```
front_camera_optical → front_camera → base_link → odom → map
```

使用 `rospy.Time(0)` 查询最新可用的 TF，避免时间戳不同步导致的查询失败。

变换后得到 `(map_x, map_y, map_z)` — 箱子在全局地图中的坐标。

## 4. 去重部分（3D 聚类 + 投票）

这是整个系统的核心。同一个箱子在巡逻中被多次看到，需要合并为同一个候选。

### 4.1 数据结构：BoxCandidate

每个 `BoxCandidate` 代表地图上的一个物理箱子：

```python
class BoxCandidate:
    x, y, z          # 地图坐标（持续做滑动平均更新）
    votes = {digit: count}  # 每个数字收到的投票数
    obs_count         # 观测次数（用于位置平均）
```

### 4.2 聚类逻辑

当一次检测产生了地图坐标 `(mx, my)` 和数字 `digit`：

```
1. 遍历所有已有候选，计算欧氏距离
2. 找到距离最近的候选
   - 如果 距离 < cluster_radius (1.0m) → 归入该候选，增加投票
   - 如果 距离 >= cluster_radius 或无候选 → 创建新候选
```

**cluster_radius = 1.0m** 的选择依据：
- 箱子尺寸：0.8m × 0.8m
- 箱子最小间距：约 1.5m
- 半径设为 1.0m 既能容纳同一箱子不同角度的定位偏差，又不会把相邻箱子错误合并

### 4.3 投票机制

每次同一候选被检测到，数字得到一票。最终该候选的数字取**票数最高的数字**：

```
候选 A 被看到 5 次：
  votes = {3: 4, 8: 1}
  → best_digit = 3（多数投票胜出）
```

这样即使偶尔一次误识别（把 3 看成 8），多数投票仍能给出正确结果。

### 4.4 位置滑动平均

每次新观测归入已有候选时，用**递增平均**更新坐标：

```python
alpha = 1 / obs_count
x_new = x_old + alpha × (x_observed - x_old)
```

随着观测次数增加，新观测的权重越来越小，位置趋于稳定。

### 4.5 确认阈值

```python
min_confirm_votes = 1  # 至少被检测到 1 次才计入最终计数
```

当前设为 1（即首次看到就计数）。如果环境中误检较多，可以调高此值（如 2 或 3），要求多次确认才计数。

### 4.6 冷却机制

同一数字在被成功 3D 定位后，进入 10 帧的冷却期（`cooldown_frames = 10`），在此期间不再为该数字触发新的 3D 定位和投票。这避免了连续帧对同一个箱子重复投票过多。

## 5. 输出

### 5.1 计数结果

发布到 `/box_detector/counts`，格式为 Python 字典字符串：

```
{1: 2, 3: 1, 5: 3}  # 表示数字1出现2个箱子，数字3出现1个，数字5出现3个
```

### 5.2 最少数字

发布到 `/mission_planner/min_box_id`，输出当前计数最少的数字编号（用于导航决策）。

### 5.3 可视化图像

发布到 `/box_detector/image`，在 RGB 画面上叠加：
- 检测框（绿色=普通检测，红色=新箱子，橙色=已有候选投票）
- 数字编号、匹配得分、深度值
- 左上角显示去重后的各数字计数

### 5.4 地图标记

发布到 `/box_detector/markers`（MarkerArray），在 RViz 2D 地图上显示：
- 每个候选箱子位置画一个彩色立方体（颜色按数字区分）
- 立方体上方显示数字编号和投票数
- 已确认的候选透明度 0.7，未确认的 0.3

## 6. 参数汇总

| 参数 | 当前值 | 说明 |
|------|--------|------|
| `cluster_radius` | 1.0m | 聚类半径，同一半径内的检测归为同一箱子 |
| `min_confirm_votes` | 1 | 最少投票数才算有效候选 |
| `count_threshold` | 0.60 | 模板匹配得分 ≥ 此值才触发 3D 定位 |
| `draw_threshold` | 0.45 | 得分 ≥ 此值在画面上画框（不计数） |
| `min_detect_size` | 25px | 缩放后模板最小边长 |
| `min_depth` | 0.3m | 忽略过近的深度值 |
| `max_depth` | 10.0m | 忽略过远的深度值 |
| `depth_patch_size` | 5 | 深度中值滤波的 patch 大小 |
| `cooldown_frames` | 10 | 同一数字的检测冷却帧数 |
